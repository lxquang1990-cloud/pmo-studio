# Product Hardening Checklist

This checklist defines the non-UX hardening bar for PMO Studio releases.

## Release hygiene

- `pyproject.toml`, `pmo_studio.__version__`, CLI description, README, and release docs agree on the current version.
- README documents the golden path and links to known limitations.
- Changelog contains the current release section.
- Build artifacts are generated by release automation; source commits should avoid unnecessary binary artifact churn.

## Security and privacy

- Source uploads remain project-local.
- Customer ZIP bundles do not contain `source/uploads/`.
- Customer ZIP bundles do not contain `source/redacted/` unless explicitly requested.
- Redaction tests cover API keys, tokens, passwords, email addresses, phone numbers, and prompt-injection markers.
- LLM mode is opt-in and redacted source is the intended LLM input.

## Reliability

- Golden path command completes offline with `--llm noop`.
- Traceability validation passes for golden path sample.
- Quality gates pass for golden path sample.
- Export pack is readable and includes manifest metadata.
- `pmo doctor` passes in a fresh editable install.

## Benchmarking

- Built-in benchmark suite runs without external services.
- Real-world benchmark cases have explicit expected modules, out-of-scope markers, and estimate sanity bounds.
- Benchmark report records pass/fail, trace edges, gate pass rate, redaction status, and quotation sanity.

## Approval and governance

- Final sign-off and official quotation remain human-governed.
- Re-export after final approval requires explicit force.
- Baselines and change requests are auditable.
